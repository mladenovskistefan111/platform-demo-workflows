# How a service calls them

Two small files per service (generated by `tools/gen-callers.py`). `ci.yaml` runs on pull requests, `release.yaml` runs when a
`vX.Y.Z` tag is pushed or by hand. **Nothing runs on a plain push.**

```yaml
# .github/workflows/ci.yaml (shape)
on: { pull_request: { branches: [main] }, workflow_dispatch: }
permissions: {}
jobs:
  go:     { permissions: { contents: read, pull-requests: read }, uses: .../go-ci.yaml@<sha> # v3.0.3 }
  image:  { needs: go, permissions: { contents: read, packages: write }, uses: .../docker-build.yaml@<sha> # v3.0.3 }
  workflows: { permissions: { contents: read }, uses: .../workflow-lint.yaml@<sha> # v3.0.3 }
# release.yaml adds:  promote: { needs: [image, workflows], if: tag || inputs.publish, permissions: { id-token: write, ... },
#                                uses: .../docker-promote.yaml@<sha>, secrets: DOCKERHUB_USERNAME / DOCKERHUB_TOKEN }
```

Callers always pin to a **commit SHA** with the version in a trailing comment. A reusable workflow can never get more permissions
than its caller grants, so each job lists what it needs (`id-token: write` only on `promote`). Secrets used: `DOCKERHUB_USERNAME`,
`DOCKERHUB_TOKEN` (per service repo). Semgrep needs no token any more.
